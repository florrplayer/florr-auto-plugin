# florr.io 怪物静态属性与刷怪权重 深度挖掘报告

> 本报告全部数值来自 `data/` 下本地静态文件，未做任何外部补全或编造。

> 复现脚本：`data/mob_data_miner.py`；掉落解析中间表：`data/_dropchance_resolved.tsv`。

> 数据快照：怪物 73 只、花瓣 118 种、threat 数值表 73 条、dropchance 键 332 个。


## 0. 数据来源与字段口径

| 文件 | 作用 | 关键字段 |
|---|---|---|
| `all_mobs_full.json` | 73 怪 NDJSON | id / sid / drops[{baseChance,type}] / rarities[].tooltip |
| `mob_threat.json` | 每怪全稀有度数值(已整理) | dmg[] hp[] hp_hi[] armor[] exp[] drops[][] |
| `wasm_map_data.json` | 每图刷怪权重 + 传送门 | maps.<图>.mobs{sid:权重} |
| `florr_dropchance.json` | 精确掉落概率 | `"怪id|花id|稀有度档"→概率` |
| `all_petals_full.json` | 118 花 NDJSON | id / sid（用于把掉落 type 翻译成花名） |
| `mob_spawn_data.json` | 生成播报 + 生成机制字符串 | mob_spawn_chats / spawn_mechanics |
| `mob_stats_full.json` | 带稀有度档名的怪物表 | rarity: Common/Rare/Super/Epic/Legendary/Mythic/Ultra |

**稀有度档位口径**：`mob_threat.json` 每怪有 7 个数值档位（Common→Ultra），`all_mobs_full.json` 的 rarities 数组更宽（含更高档 {} 结尾）。相邻档位数值约 ×3 增长（HP/dmg/armor），这是 florr 的稀有度缩放规律。

### 2b. 权重解读与稀有怪推算

- **garden**：纯枢纽（portal 通往 desert/ocean/jungle/anthell），自身无刷怪权重表。
- **desert**：cactus 几乎占一半（49.4%），beetle 与 sandstorm 各 ~24.7%；`ladybug_shiny=0.025`。
- **ocean**：5 怪均分，各 20%（crab/jellyfish/leech/shell/sponge 权重全为 1）。
- **jungle**：leafbug 与 mantis 各 38.1%，wasp 19.0%，firefly 3.81%，`centipede_evil=0.025`。
- **anthell**：ant_soldier 权重 10 极高（61.4%），ant_worker 5（30.7%），ant_queen 1（6.1%），worm 0.3（1.8%）。
- **sewers**：spider 权重 1（54.1%），silverfish/garbage 0.3，moth 0.25；无 portal 字段。

**关于 `ladybug_shiny=0.025`（及 `centipede_evil=0.025`）的推算方式：**

1. 它不是“2.5% 替代率”，而是**权重表内的原始权重值**。
2. desert 权重总和 = 1 + 0.5 + 0.5 + 0.025 = **2.025**；归一后 ladybug_shiny 占比 = 0.025/2.025 ≈ **1.23%**。
3. 同理 jungle 总和 = 1+0.1+0.5+1+0.025 = 2.625；centipede_evil 占比 = 0.025/2.625 ≈ **0.95%**。
4. 结合 `mob_spawn_data.spawn_mechanics`：`super_announced=true`（Super 怪全服广播）、`super_random_replace`（Super 是 Ultra 怪的极低概率随机替换）、`super_not_time_based`（不是超时刷的）。因此 0.025 权重更应理解为：在常规刷怪池中以 ~1% 量级被抽中，且一旦刷出会触发全服播报（desert 对应 `mob_spawn_chats` 里的闪光/特殊播报）。**绝对“多久刷一只”的时间频率无法从静态权重推出，需服务器刷怪间隔参数，静态文件中没有。**

**各图 spawn 机制差异（来自 `mob_spawn_data.json`）：**

- 专属生成播报：rock / cactus / hornet / jellyfish / firefly / gambler 等出现时聊天栏有专属英文播报。
- 生成机制字符串：`luck_affects_rarity=true`（幸运影响稀有度）；`ultra_freq` ≈ Ultra 生成频率约 10 倍提升、掉率 3–4 倍降低；`eggs_hatch_on_break`（蛋只有打破时才孵化）；`super_not_time_based`（Super 非超时触发）。
- `wasm_map_data.secret_routes`：ocean/anthell 各有 3 条隐藏路线（br/ocean_1..3、br/ant_hell_1..3），`from_garden = br/ocean, br/ant_hell`。这些是隐藏区域入口，权重表不含其中的怪。



## 3. 精确掉落概率表（florr_dropchance.json 解析）

**Key 三段含义（已用映射核对）：** `怪id | 花id | 稀有度档`
- 第 1 段 = 怪物 id，与 `all_mobs_full.json` 的 `id` 对应（如 4=bee、5=ant_baby、82=ant_soldier_diver）。
- 第 2 段 = 花瓣 id，与 `all_petals_full.json` 的 `id` 对应（如 6=stinger、51=ant_egg、114=dead_leaf）。
- 第 3 段 = 稀有度档，**全部键只出现 `5` 与 `6` 两档**（共 332 键，档5 有 167 条、档6 有 165 条）。

**数值特征：** 对每一对 (怪,花)，档5 的值极小（量级 1e-9 ~ 1e-148，可视为近乎不可能），档6 的值为主概率（0.51 ~ 0.96）。两档之和介于 0.089 ~ 1.0 之间，并非每对都恰好为 1。

⚠️ **口径保留**：静态 JSON 能确定的是“三段 = 怪/花/档∈{5,6}”及数值本身；档 5/6 精确对应游戏内哪两个花瓣稀有度名、以及该值是“每杀期望概率”还是“掉落后的条件稀有度分布”，无法仅凭静态文件判定，需对照 wasm 或 florr 维基确认。下表数值原样列出。

## 5. AI 相关静态参数存在性结论

对 `all_mobs_full.json / mob_stats_full.json / mob_threat.json / mob_hp.json` 全量扫描键名（正则：speed|range|aggro|attack|move|sight|chase|follow|accel|velocity）。

- **怪物对象的全部字段只有四个：`id` / `sid` / `drops` / `rarities`。**
- `rarities[].tooltip` 里与战斗相关的属性仅有：**HealthRange（HP范围）、Damage（伤害）、Armor（护甲）、exp（经验）**。
- **静态数据中不存在 attackRange（攻击距离）、movementSpeed（移动速度）、aggro（仇恨范围）等任何 AI 行为参数。**（命中的 `HealthRange` 是血量区间，与攻击距离无关；`isPassive` 出现在花瓣 antennae 上，不是怪物字段。）

**结论：** 攻击距离、移动速度、仇恨/追击逻辑等 AI 参数**不在这批静态 JSON 内**，需通过 client.wasm 逆向（可参考 `florr_wasm_strings.txt`，1.5MB 字符串）或 florr.io 维基获取。插件若需要“贴近怪保持距离”“预判走位”等战斗策略，只能拿到 **HP/伤害/护甲/经验/掉落/刷怪权重** 这一侧的静态依据，AI 侧数值需另行采集。


## 6. 对插件（auto-pathing / 战斗策略）的数据支撑

| 策略需求 | 可用静态数据 | 结论 |
|---|---|---|
| 选图刷怪效率 | §2 每图权重归一占比 | anthell 刷怪密度最高（ant_soldier 权重 10）；ocean 五怪均分最稳 |
| 目标怪稀有度判断 | §2b ladybug_shiny/centipede_evil 权重 0.025→归一~1% | 闪光/邪恶怪为低权重事件怪，刷出即广播，优先追 |
| 伤害/血量预算 | §1/§4 HP范围、Damage、Armor 全档位 | 可按当前档位 ×3 缩放预判需要的 DMT/EHP |
| 护甲穿透决策 | Armor 逐档（1→2→7→22→65→194→583） | 高档护甲骤增，纯攻击流后期需破甲/真伤思路 |
| 掉落farm路线 | §3 dropchance + §1 地图权重 | 结合“怪权重×掉落概率”可算期望产率，定位高效farm点 |
| Boss/特殊怪遭遇 | §4 七只特殊怪全档数值 | gambler/pharaoh/diver 高档 HP 达千万级，需提前准备 |
| 走位/仇恨距离 | — | ❌ 无 AI 参数，静态数据支撑不了，需 wasm/维基补 |

**一句话总结：** 静态数据足以支撑“刷怪密度选图、掉落期望路线、HP/伤害/护甲数值预算、特殊怪识别与优先级”，但**攻击距离与移动速度等 AI 行为参数缺失**，走位类策略需后续逆向 wasm 补充。
